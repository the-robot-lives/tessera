# Hologram demo — tessera components in a Hologram 0.10.1 host

A minimal, DB-free Hologram app (Phoenix + Bandit + `Phoenix.PubSub`, no
Ecto) that consumes the `persona_kit` example package — itself a real Mix
package path-depping on the tessera library. This is the reference recipe
for docs/CONSUMING.md.

## Run it

```sh
cd demo/hologram_app
mix deps.get          # pulls hologram/phoenix + the path deps
mix tessera.install   # wires @noizu/tessera-core + lit into assets/package.json, npm install
mix holo              # compiles (incl. the Hologram client bundle) and serves on port 5586
```

Then open **http://localhost:5586** (main page) and
**http://localhost:5586/second** (Link round-trip page).

Notes:

* `mix holo` = `phx.server` with `HOLOGRAM_START=1`. In dev the Hologram
  client bundler only runs when `HOLOGRAM_START=1` (or outside dev/test) —
  a plain `mix compile` skips client bundling by design.
* No database: the endpoint needs only Plug.Session + the Hologram router.
* `assets/` is fully generated by `mix tessera.install` (gitignored), and
  the client bundles land in `priv/static/hologram/` (gitignored).

## What the main page proves

| panel | scenario | wire mechanism |
|---|---|---|
| (a) | stateless `<PersonaCard on_persona_select={:chose}/>` | bridge dispatches `:chose` at the page; page state re-renders |
| (b) | stateful `<PersonaCard cid="p1" on_persona_select={{:chose, target: "p1"}}/>` | bridge dispatches at the card's cid; the card action chains `:cid_confirmed` at the page (`put_action(target: "page")`) as observable proof the cid targeting ran |
| (c) | `<PersonaPicker>` nested-shadow re-emit | child `persona-select` stays private; picker re-emits `persona-picked` → page `:pick` |
| (d) | `behaviors.add` extension (EXTENDING.md §2) | `EnrichedPanel` installs a behavior via a `js_import`-ed module (client-side JS interop in an action handler), then mounts a FRESH card to prove behaviors apply to later connects (`data-tessera-enriched`) |
| (e) | `/second` `<Link>` round trip | elements hydrate after client-side navigation; no `NotSupportedError` |

The Cypress e2e suite (demo/e2e) drives all five plus the plain-HTML demo.
